게시판 추천 관련 메모

추천은 로그인한 사용자가 게시글마다 한 번만 할 수 있게 했다. 날짜가 바뀌어도 다시 추천할 수 없고, 추천 취소는 아직 없다. 추천한 사람은 요청에서 받지 않고 로그인 세션으로 확인한다.

목록에는 likeCount, 상세에는 likeCount와 likedByMe를 내려준다. 추천 요청은 POST /api/community/posts/{postId}/likes이고, 이미 추천한 글이면 409를 반환한다. 게시글을 삭제하면 해당 글의 추천 기록도 함께 삭제된다.

추천 기록은 board_post_like에 저장한다. post_id와 user_id로 기존 board_post, site_user를 참조하고, 같은 사람이 같은 글을 두 번 추천하지 못하도록 (post_id, user_id)에 고유 제약을 둔다. created_at은 다른 게시판 엔티티처럼 LocalDateTime/TIMESTAMP를 사용한다. 초기 데이터는 필요 없다.

이 테이블은 아직 팀 DB에 적용하지 않았다. DB 담당자가 기존 테이블과 board_post_like의 유무를 먼저 확인하고, 실제 스키마와 아래 SQL을 비교한 뒤 적용해야 한다. 이미 테이블이 있으면 다시 만들지 말고 컬럼과 제약 조건을 확인하면 된다. collector는 ddl-auto가 validate라서 테이블이 준비되기 전에 실행하면 시작에 실패할 수 있다.

CREATE TABLE board_post_like (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    post_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    created_at TIMESTAMP NOT NULL,
    CONSTRAINT fk_board_post_like_post FOREIGN KEY (post_id) REFERENCES board_post (id),
    CONSTRAINT fk_board_post_like_user FOREIGN KEY (user_id) REFERENCES site_user (id),
    CONSTRAINT uk_board_post_like_post_user UNIQUE (post_id, user_id)
);

게시판 변경 요청에는 세션 CSRF 토큰을 사용한다. 로그인 후 GET /api/community/csrf로 토큰을 받고, 프론트에서 글·댓글·추천 변경 요청의 헤더에 넣어 보낸다. 토큰이 없거나 맞지 않으면 403이다. 현재 적용 범위는 /api/community/**다.
