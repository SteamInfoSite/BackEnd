# 게시글 추천

## 정책

- 로그인한 사이트 회원은 게시글마다 한 번만 추천할 수 있습니다. 날짜가 바뀌어도 다시 추천할 수 없습니다.
- 추천 취소는 지원하지 않습니다. 본인 글 추천은 허용합니다.
- 비로그인 사용자는 추천 수를 볼 수 있지만 추천을 등록할 수 없습니다.
- 추천자는 요청 본문이 아닌 Steam 로그인 세션과 `site_user`에서 확인합니다.
- 게시글을 삭제할 때 해당 글의 추천 기록도 삭제합니다. 회원 삭제 정책은 이 기능에서 변경하지 않습니다.

## API

| 요청 | 응답 | 오류 |
| --- | --- | --- |
| `GET /api/community/posts?page=1&size=20` | 각 `items`에 `likeCount` 추가 | 기존 목록 오류와 동일 |
| `GET /api/community/posts/{postId}` | `likeCount`, `likedByMe` 추가. 비로그인은 `likedByMe: false` | 기존 상세 오류와 동일 |
| `POST /api/community/posts/{postId}/likes` | `200 {"likeCount": 1, "likedByMe": true}` | `400` 잘못된 ID, `401` 비로그인, `404` 글 없음, `409` 이미 추천함 |

추천 등록 요청에는 사용자 ID나 날짜를 보내지 않습니다. 동시 요청의 중복 저장은 DB 고유 제약으로 막습니다. 추천 등록 후 화면은 POST 응답으로 수를 갱신하며, 조회수가 증가하는 게시글 상세 GET을 다시 호출하지 않습니다.

## 배포 전 보안 확인

추천 등록은 기존 게시글·댓글 쓰기 API와 같은 세션 인증을 사용합니다. 현재 백엔드에는 이 변경 요청들을 보호하는 공통 CSRF 검증이 없습니다. 배포 전에 세션에 묶인 CSRF 토큰을 발급하고, 프론트가 POST/PATCH/DELETE 요청 헤더에 보내며, 서버가 이를 검증하는 방식을 게시판 변경 API 전체에 적용해야 합니다. 버튼의 비활성화나 `likedByMe` 값은 권한 검사를 대신하지 않습니다.

## DB 변경 검토

JPA Entity가 `board_post_like`를 매핑합니다. 기존 `site_user`와 `board_post`를 외래키로 참조하며 `(post_id, user_id)`가 고유합니다. 시각 컬럼은 기존 게시판과 같은 `LocalDateTime`/`TIMESTAMP`를 사용합니다. 초기 데이터는 없습니다.

아래 DDL은 검토용입니다. 이 문서를 DB에 실행하지 않았습니다.

```sql
CREATE TABLE board_post_like (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    post_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    created_at TIMESTAMP NOT NULL,
    CONSTRAINT fk_board_post_like_post FOREIGN KEY (post_id) REFERENCES board_post (id),
    CONSTRAINT fk_board_post_like_user FOREIGN KEY (user_id) REFERENCES site_user (id),
    CONSTRAINT uk_board_post_like_post_user UNIQUE (post_id, user_id)
);
```

현재 기본 설정은 `ddl-auto: update`이므로 변경된 백엔드를 개발용 PostgreSQL에서 시작하면 Hibernate가 새 테이블을 생성할 수 있습니다. 팀 DB에 적용하기 전에 담당자가 실제 스키마와 적용 방법을 검토해야 합니다. 기존 테이블과 데이터의 삭제·초기화는 필요하지 않습니다.
